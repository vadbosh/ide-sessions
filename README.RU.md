# ide-sessions

**Три команды, которые показывают, суммируют и чистят сессии Claude Code,
Codex CLI и opencode — включая ту, которую вы потеряли.** Четвёртая,
`billing`, показывает, во что они обошлись: по дням, неделям или месяцам сразу
для всех трёх IDE или для одной сессии по её id.

## Зачем нужен ide-sessions

Задачи две — по одной на каждую половину инструмента.

**Где сессия лежит на самом деле.** Каждая IDE раскладывает сессии по своему
правилу, и ни одно из них не совпадает с каталогом, в котором вы её ищете.
Claude Code берёт путь, откуда запустили `claude`, и больше к этому не
возвращается — даже если внутри работающей сессии перейти в другой каталог.
Запустили в каталоге одного кластера, весь день проработали по другому: сессия
всё равно числится за первым, и `--resume` не найдёт её там, где вы смотрите. У
Codex файл лежит под датой начала, а она расходится с датой работы, как только
сессию продолжили на следующий день. У opencode каталог хранится колонкой в
базе — запросить легко, увидеть из CLI нечем. Все три списка показывают id,
каталог, за которым сессия числится на самом деле, и насколько она свежая.

**Что в ней было.** Чтобы вспомнить, транскрипт надо перечитать целиком.
`--sum` вместо этого даёт 2–4 тезиса на тему, максимум пять тем — и всегда на
английском, на каком бы языке сессия ни шла, чтобы сводку мог пробежать глазами
человек, который эту сессию не вёл.

## Установка

```bash
git clone <этот репозиторий> ide-sessions
cd ide-sessions
./install.sh              # копирует четыре команды в ~/.local/bin
./install.sh --dry-run    # сначала посмотреть, что произойдёт
```

Установщик сообщает, какие IDE нашёл и какие CLI доступны для `--sum`. Трём
командам для сессий нужен только `python3`, и все три можно поставить на машину
с одной IDE — остальные просто скажут, что ничего не нашли. `billing` нужны ещё
[ccusage](https://ccusage.com) (`npm install -g ccusage`) и `jq`: установщик
сообщает, есть ли они, а `billing` без них подскажет, как их поставить.

Удалить: `./install.sh --uninstall`.

## Использование

Просмотр, удаление и чистка одинаковы во всех трёх командах:

```bash
claude-sessions                     # все сессии, свежие сверху
claude-sessions -n 20               # ограничить число строк
claude-sessions k8s                 # фильтр по подстроке каталога
claude-sessions -p                  # только сессии текущего проекта
claude-sessions -f                  # полные пути вместо последних трёх частей

claude-sessions --rm <ID>                    # спросит подтверждение и удалит
claude-sessions --older-than 30              # покажет список, не удалит ничего
claude-sessions --older-than 30 --apply      # УДАЛИТ всё, к чему не обращались 30+ дней
claude-sessions -p --max-turns 20 --apply    # УДАЛИТ короткие сессии этого проекта
claude-sessions -p --rm-all --apply          # УДАЛИТ все сессии этого проекта
claude-sessions k8s --rm-all                 # покажет, что ушло бы, по каталогам с k8s
```

Любая массовая форма сначала показывает список и удаляет только с `--apply`.
В `--help` у каждой строки стоит глагол: «старше 30 дней» описывает отбор и
ничего не говорит о том, что с ним произойдёт.

`--rm-all` без сужения не работает. Сам по себе он означал бы все сессии всех
проектов, а именно в таком виде его набирают первым — раньше, чем прочитают про
флаг области. Назовите область через `-p` или подстроку, либо попросите
сплошную чистку по имени:

```bash
claude-sessions --rm-all                   # откажется, объяснит, вернёт 1
claude-sessions --rm-all --everywhere      # все проекты — и всё равно сначала показ
```

Удаление переносит файлы в `~/.cache/ide-sessions-trash/<ide>-<timestamp>/`,
поэтому ошибка обратима. Названный id — уже достаточное намерение, чтобы
удалить после подтверждения; массовые критерии могут захватить куда больше, чем
ожидалось, поэтому они сначала только показывают список и ждут `--apply`.
Текущая сессия не удаляется никогда.

Сводки:

```bash
claude-sessions   --sum <ID>          # сводка на английском, по темам
codex-sessions    --sum <ID>
opencode-sessions --sum <ID>

claude-sessions --sum <ID> --sum-raw       # только выжимка — без модели и без затрат
claude-sessions --sum-orig <ID>            # на языке самой сессии
claude-sessions --sum <ID> --sum-gap 90    # 90 минут тишины начинают новую тему
claude-sessions --sum <ID> --sum-refresh   # игнорировать кэш, спросить заново
claude-sessions --sum <ID> --sum-model X   # суммировать конкретной моделью
```

`--sum-orig <ID>` пишет сводку на языке, на котором шла сессия; если языков
было несколько — на том, которым больше писал пользователь. Кэшируются они
раздельно, поэтому у одной сессии могут лежать английская сводка для коллеги и
русская для себя, и одна не затирает другую.

Та же сессия глазами каждой команды — эта шла по-русски:

```
$ codex-sessions --sum 01a05994-7729-7e32-99c9-f6b53f98199e
### File listing tool replacement
- Diagnosed `--group-directories-first` sorting bug in uutils coreutils 0.8.0.
- Replaced the `ll` alias with an eza-based one, fixed the time format.

$ opencode-sessions --sum-orig ses_fa66c4184ffepvA00VLoagntRt
### Исправление сортировки в alias ll
- Выявлен дефект в uutils coreutils 0.8.0: `--group-directories-first`
  отменяет сортировку по имени.
- Удалён мёртвый alias `lld`, вызывавший отсутствующую команду `lsd`.
```

## Стоимость: `billing`

`billing` отвечает на два вопроса: сколько ушло за день, неделю или месяц и во
что обошлась одна сессия. Сам он ничего не считает: те же локальные логи, что
читают три другие команды, читает и оценивает [ccusage](https://ccusage.com), а
`billing` выбирает отчёт и раскладывает его в таблицу.

```bash
billing                           # последние 20 дней, все IDE, стоимость по каждой
billing week --since 2026-09-01   # недели начиная с даты
billing month --ide codex         # одна IDE по месяцам
billing -n 0                      # все периоды, а не последние 20
billing --id <ID>                 # одна сессия: токены, кэш, стоимость, по моделям
billing --id <ID> --ide codex     # если такое начало id есть в двух IDE
billing live                      # текущий 5-часовой блок
billing --json                    # JSON самого ccusage вместо таблицы
```

`<ID>` — тот id, который показывают команды для сессий: `claude-sessions`,
`codex-sessions`, `opencode-sessions`. Хватает уникального начала. Сессию Codex
ccusage называет путём к её стенограмме; `billing` сравнивает uuid в конце этого
пути, поэтому id из `codex-sessions` подходит как есть. Если под начало id
подходят несколько сессий, `billing` перечислит их, а не выберет одну наугад.

```
$ billing --id bdc2f598
  IDE:           claude
  Session:       bdc2f598-3b6a-4e6f-a648-10ba0f1d4360
  Models:        claude-opus-5-5
  Started:       2026-09-11T09:40:02Z
  Last activity: 2026-09-11T09:59:41.210Z

  MODEL                           INPUT      OUTPUT     CACHE_WR        CACHE_RD           TOTAL CACHE%       COST
  claude-opus-5-5                   412      96,318      288,051      24,110,907      24,495,688    98%      $9.12
  TOTAL                             412      96,318      288,051      24,110,907      24,495,688    98%      $9.12
```

- **CACHE_WR / CACHE_RD** — сколько токенов записано в кэш промпта и прочитано
  из него.
- **TOTAL** — вход + выход + запись в кэш + чтение из кэша.
- **CACHE%** — доля чтения из кэша в TOTAL: сколько контекста взято повторно, а
  не оплачено заново.
- **COST** — оценка: токены, умноженные на цену модели. На подписке это
  столько, сколько та же работа стоила бы через API, а не списанные деньги.
- **Модель** — та, которую API указал в каждом ответе, а не та, с которой
  сессию начали: переключение `/model` посреди сессии даст вторую строку.

## Как работает `--sum`

В два прохода.

**Локально** сессия сжимается в выжимку: о чём просили, короткие куски ответов,
счётчик по каждому инструменту — разбитые на части там, где работа реально
останавливалась (тишина дольше `--sum-gap` или смена каталога). Всё, что сводке
не пригодится, отбрасывается здесь же: вывод инструментов, болтовня хуков,
обвязка слэш-команд, вставленные преамбулы скиллов и AGENTS.md, ветки
субагентов. `--sum-raw` печатает ровно это и не стоит ничего.

**Дальше один вызов модели** превращает выжимку в заголовки и тезисы. Этот шаг
локально не сделать: сессии идут на русском, английском, немецком или на смеси
внутри одного предложения, а сводка должна вернуться на английском.

Каждая команда зовёт **CLI своей же IDE** — `claude -p`, `codex exec`,
`opencode run`. На машине с Codex может не быть Claude Code, поэтому привязка
функции одного инструмента к бинарнику другого сделала бы её недоступной ровно
там, где она нужна.

Этот вызов сам по себе сессия, и каждая IDE её записывает. Поэтому сводка
убирает за собой — способом, который не может задеть ничего чужого:

- `claude-sessions` передаёт `--session-id`, который сам и сгенерировал, и
  удаляет ровно этот UUID;
- `opencode-sessions` даёт служебной сессии заголовок и удаляет по нему;
- `codex-sessions`, где id выбирает CLI, берёт только тот rollout, который
  одновременно появился за время вызова и содержит текст нашего промпта.
Удалять «самый свежий файл» было бы очевидным сокращением и было бы ошибкой:
Codex, запущенный в соседнем терминале, дописывает свой rollout всё это время.

### Сколько занимает сводка и где лежит

Всё ожидание — это вызов модели. Замерено на транскрипте 9 МБ, 4577 строк:

| Шаг | Время |
|---|---|
| Локальная выжимка (`--sum-raw`) | 0,6 с |
| Вызов модели: выжимка 15 КБ, 10 частей сведены в 5 тем | 79 с |
| Повторный запуск, из кэша | 0,3 с |

Минута и больше на длинной сессии — это норма, и дело не в разборе файла и не в
записи: одна модель пишет сводку по десяти отдельным кускам работы. `--sum-raw`
разделяет эти два случая: если он отвечает мгновенно, а `--sum` нет, время
уходит на стороне API.

Пока вызов идёт, работает счётчик — в stderr и только если stderr это терминал,
поэтому в пайп или в скрипт он не попадает:

```
  summarizing 10 part(s) with claude-haiku-4-5-20251001… 37s
```

**Кэш — это обычные файлы, а не база.** По одному Markdown-файлу на сессию и
язык в `~/.cache/ide-sessions-summaries/`:

```
claude-<ID>.md          английская сводка
claude-<ID>.orig.md     она же от --sum-orig
codex-<ID>.md
opencode-<ses_…>.md
```

Первая строка — комментарий с ключом: mtime транскрипта, модель, размер паузы,
язык. Дальше идёт сама сводка, как она печатается. Права `0600`, каталог
`0700`; удаление файла стоит одного повторного запуска и больше ничего. Ключ
проверяется до разбора транскрипта, поэтому попадание в кэш не делает вообще
никакой работы, а сессия, которую с тех пор продолжили, суммируется заново —
у неё сдвинулся mtime.

Ничего никогда не дописывается. Повторный запуск заменяет этот один файл
целиком: новая сводка делается по всему транскрипту, а не по куску, добавленному
с прошлого раза, — сводка последнего часа без первого была бы хуже, чем никакой.
Удаление файла или всего каталога стоит ровно одного повторного запуска, другого
состояния нет. `--rm` удаляет сводки вместе с самой сессией, в ту же корзину, из
которой всё восстанавливается.

Единственный SQLite во всей этой истории — собственная база сессий opencode,
которую `opencode-sessions` читает для списка и удаления. Сводки в неё не
пишутся никогда.

### Ключи и пароли

В сессии может оказаться ключ: вставили в промпт, модель повторила в ответе,
он вылез в тексте ошибки. Сводка унесла бы его сразу по трём адресам — в API,
которое её пишет, в файл кэша и в терминал сессии, которая её запросила, а та
тоже пишется на диск. Про API стоит сказать отдельно: сводку может делать не
тот провайдер, у которого шла сессия, — тогда ключ, набранный в одной системе,
уезжает в другую.

Поэтому выжимка маскирует значения до того, как что-либо покидает процесс, а
`--sum-raw` показывает ровно то, что было бы отправлено:

```
ASKED: deploy with <REDACTED:42> please
ASKED: export AWS_ACCESS_KEY_ID=<REDACTED:20>
ASKED: DB_PASSWORD=<REDACTED:21> in the values file
ASKED: psql postgres://<REDACTED:10>@db.internal:5432/app
ASKED: HW_ACCESS_KEY=<REDACTED:20>
ASKED: jira --token <REDACTED:38> issue list
ASKED: api token is <REDACTED:40> and it expired
ASKED: checked out 9f8e7d6c5b4a39281706f5e4d3c2b1a09f8e7d6c from main
```

Два уровня, потому что форма сама по себе решить не может.

**Уровень 1, решает форма.** `ghp_`, `github_pat_`, `AKIA`, `glpat-`, `xox…`,
`sk-` (включая `sk-ant-`, `sk-proj-`, `sk-or-v1-`), `AIza`, `sk_live_`,
`tvly-`, `hf_`, `dckr_pat_`, атлассиановские `ATATT` и `at-`, JWT, строка
`BEGIN … PRIVATE KEY`, пароль внутри URL. Маскируется везде, где встретится.

**Уровень 2, решает имя.** Huawei Cloud и OpenStack — причина, по которой этот
уровень вообще нужен. Их access key — 20 символов заглавных и цифр, secret — 40
символов base62: ровно те же формы, что у git SHA, номера сборки и половины
идентификаторов в обычном выводе. Ни один шаблон не возьмёт их, не забрав всё
остальное. Поэтому длинное значение маскируется, когда рядом стоит имя,
похожее на имя ключа:

- `HW_ACCESS_KEY=`, `HUAWEICLOUD_SDK_AK=`, `OS_SECRET_KEY:`;
- `--token`, `--pass`, `Authorization: Bearer`;
- любое имя со словом password, secret, token, credential.

Мягче — когда слово о ключах встречается где-то в строке, по-английски или
по-русски.

Последняя строка примера показывает, что даёт это условие: 40-символьный SHA,
рядом с которым нет слов о ключах, остаётся читаемым. Сводка, прячущая
собственные коммиты, ни на что не отвечает.

Jira попадает в оба уровня: у API-токена есть префикс `ATATT`, а
`jira --token …` ловится по флагу.

Промпт вдобавок запрещает выписывать ключи, файлы кэша создаются с правами
`0600`, каталог — `0700`. Ключ, который уже попал в транскрипт, это не спасает
— такой надо ротировать. Это мешает сводке скопировать его в новое место.

### Сколько стоит сводка

Цифры измерены, а не прикинуты. Неинтерактивный `claude -p` по умолчанию
подтягивает ваш `CLAUDE.md`, скиллы и MCP-серверы: однострочный промпт обошёлся
в **40 179** входных токенов. Он же с `--setting-sources ''` и пустым
MCP-конфигом — в **4 591**. Оба флага передаются. Codex для этого вызова тоже
идёт с выключенными скиллами, MCP и хуками.

Обычная сводка — один вызов по выжимке в 2–4 КБ.

### Какая модель

В скриптах не зашито ни одного имени модели и ни одной версии — зашитое имя
устаревает к следующему релизу. `--sum` и `--sum-orig` выбирают модель
одинаково: язык ответа на выбор не влияет.

**`claude-sessions`**, по порядку, побеждает первое сработавшее:

1. `--sum-model M`, иначе `IDE_SESSIONS_SUM_MODEL`.
2. Самая дешёвая модель Anthropic **с известной ценой** из каталога
   [models.dev](https://models.dev), найденного на диске:
   `IDE_SESSIONS_MODELS_JSON`, `~/.cache/ide-sessions/models.dev.json`,
   `~/.cache/opencode/models.json`. Дешевизна считается по входной цене за
   миллион токенов; модели с нулевой ценой пропускаются — ноль гораздо чаще
   значит «цены здесь нет», чем «бесплатно», — и те, у кого контекст меньше
   100k. Сети не требуется: каталог берётся, только если он уже лежит.
3. `haiku` — собственный алиас CLI, который сам следует за текущей малой
   моделью.
4. Модель, которую CLI выберет сам, если предыдущий вызов не прошёл: аккаунт
   может не иметь доступа к выбранной. В строке про модель тогда стоит
   `(CLI default)`.

**`codex-sessions`**:

1. `--sum-model M`, иначе `IDE_SESSIONS_SUM_MODEL` — уходит в `codex exec -m`.
2. Иначе модель, на которую настроен Codex: поле `model` в
   `~/.codex/config.toml` либо его собственное значение по умолчанию. У Codex
   одно семейство моделей на аккаунт и никакого прайс-листа на диске, выбирать
   не из чего. Выбирается вместо этого глубина: `model_reasoning_effort="low"`,
   потому что выжимке рассуждения не нужны.

**`opencode-sessions`**:

1. `--sum-model M`, иначе `IDE_SESSIONS_SUM_MODEL` — уходит в
   `opencode run --model provider/model`.
2. Иначе флаг `--model` не передаётся вовсе, и работает собственный порядок
   opencode: поле `model` в конфиге, затем последняя использованная модель.
   Выбрать модель подешевле из каталога тут можно, и сознательно не сделано.
   У opencode ~385 моделей у разных провайдеров, доступность различается от
   машины к машине и от логина к логину. Сводка, молча посчитанная на модели,
   которую пользователь не настраивал, хуже сводки подороже.

Какая модель написала сводку, печатается в stderr, поэтому `--sum | …` остаётся
чистой сводкой:

```
$ claude-sessions --sum <ID> > /tmp/s.md
summarized with claude-haiku-4-5-20251001
```

## Особенности по IDE

Пустой результат всегда называет область, которая оказалась пустой. Частый
случай — `-p` в каталоге, где сессий никогда не было; это не ошибка: Claude
Code выводит каталог проекта из cwd, и у каталога, откуда его не запускали,
его просто нет.

**Claude Code** — один `.jsonl` на сессию в `~/.claude/projects/<hash>/`. Сессия
— это не только транскрипт: логи субагентов, история файлов, окружение сессии,
данные об использовании и состояние предупреждений безопасности привязаны к
тому же id, и `--rm` переносит в корзину весь этот след целиком.

### Почему старой сессии нет в списке

Удаляет что-либо только Claude Code. Он чистит транскрипты старше
`cleanupPeriodDays` из `settings.json` — по умолчанию 30 дней — и забирает при
этом `.jsonl`, оставляя каталог проекта и всё остальное, что в нём лежит.
Каталог с заметками и без единой сессии — обычный вид сессии, которая вышла за
срок. Поднятие настройки не возвращает то, что предыдущий прогон уже удалил.

Codex и opencode не удаляют ничего: ни по времени, ни по размеру, настраивать
нечего. Секция `[history]` в `config.toml` у Codex управляет
`~/.codex/history.jsonl` — историей промптов, а не rollout-файлами. Самая старая
сессия у них — это просто день, когда IDE начали пользоваться, и убрать её может
только `--rm`.

**Codex** — один `rollout-*.jsonl` на сессию. В ходу две раскладки: до
codex-cli 0.135 реплики лежат в `event_msg/user_message`, с 0.154 — в
`response_item/message` с полем роли. Читаются обе, а файл, в который писали и
до обновления, и после, не считает свои реплики дважды.

**opencode** — база sqlite. Сессия — это строки в восьми таблицах; схема
объявляет `ON DELETE CASCADE`, но `PRAGMA foreign_keys` по умолчанию выключен,
поэтому каждая таблица чистится явно в одной транзакции, а дочерние сессии
(субагенты) удаляются вместе с родителем. Перед удалением строки выгружаются в
корзину как INSERT-операторы. Запросы идут через встроенный в Python модуль
`sqlite3`, а не через CLI `sqlite3`: это отдельный пакет, которого часто нет —
там, где его не было, скрипт печатал `sqlite3 not found` и не показывал ничего.

Запуск `opencode run` заводит собственную сессию, поэтому `--sum` удаляет эту
служебную сессию после себя — по заголовку, который ей и дал.

## Тесты

```bash
tests/test_sessions.sh
```

Каждый тест строит одноразовое хранилище во временном каталоге — ни один тест
не трогает настоящие транскрипты и ни один не зовёт модель. Проверяется
выжимка: это та часть, которая может быть неверной незаметно, потому что модель
с готовностью просуммирует выжимку, набитую мусором от хуков.

`billing` проверяется с заглушкой вместо ccusage, которая печатает заготовленный
JSON в том виде, в каком его пишет ccusage: ошибиться здесь можно в раскладке
таблицы и в поиске сессии, а цены — забота самого ccusage.

## Как присылать правки

Сообщения коммитов пишутся по-английски, вместе с телом. История — единственное
место, где остаётся причина изменения, а кто читает код, прочитает и сообщение.
Если сообщение цитирует русский текст — переименованный заголовок, заменённое
слово, — цитата остаётся: там русский и есть предмет.

Сама документация двуязычная и такой остаётся: `README.md` и `README.RU.md`
правятся парой.
